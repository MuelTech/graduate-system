## Page-specific design pass (source inspection before implementation)

No browser/manual execution is included. These decisions follow inspection of the
actual current page components and their authoritative response contracts.

| Surface / actor / task | Main question and primary action | Primary facts and supporting evidence | Duplication, workflow and responsive decisions |
| --- | --- | --- | --- |
| Assign Applicant / Admin / assign a registered Applicant today | Is this Applicant eligible, and which schedule has space? Review Assignment, then Confirm Assignment. | Identity/Program/clearance in selected Applicant summary; eligibility in one status; schedule and capacity in choice or confirmation. | Replace inverse eligibility and redundant blockers with canonical copy; retain authoritative reason mapping and all guards. Do not tell Admin to contact itself. Native radio group, dialog labels, scrolling and pending dismissal guards remain. |
| Pre-start / Applicant / begin the assigned examination | When can I start, and is Start available? Start Examination. | Program and appointment once under Scheduled Examination; one availability message using server canStart/reason. | Remove repeated not-started status, authorization/configuration/recovery narration. An early-time reason supplies the approved start-time message; other failures use safe availability copy. Never infer Start permission from device time. Stack actions on narrow widths. |
| Exam Configuration / Admin / maintain settings | What values govern new examinations? Save Configuration. | Existing four typed fields and units; concise guidance; saved completeness; fixed Timezone as supporting text. | Keep validation, nullable draft persistence and frozen-start semantics. Timezone needs no read-only explanation. Keep field grid stacking, labels and pending/focus behavior. |
| Submitted / Applicant / confirm submission and find status | Was it submitted and what happens next? View Examination Status. | Success heading/confirmation; Submitted timestamp; authoritative answer counts; Awaiting evaluation. | Receipt/start in native secondary Submission details; deadline removed from primary display. Complete/incomplete summaries differ. Expiry acknowledges last saved answers without claiming explicit submission. One styled navigation action; wrapping reference and narrow reading width. |
| Exam Record / Admin / review outcome and perform the next authorized task | What is the current result, what supports it, and what can I do? Grade/finalize, appointment action or reconsideration only when authorized. | Identity in header; current result and immutable score evidence first; timing together; essay prompt/response/evaluator/time in Essay Evaluation; reconsideration reason/actor/date only when relevant. | Remove Current Exam State and Exam Information duplicates. Normal result appears once; reconsidered record leads with Final Decision and retains Computed Result once. Timing has Scheduled/Started/Ends; authorization only before start. Appointment controls follow timing; grading follows essay evidence; reconsideration follows essay section. Compact score grid stacks; long response wraps. Existing shared dialogs retain focus and mutation guards. |

Audit metadata remains persisted. Historical/unknown start and result evidence must
stay explicitly unknown. Result Notification and all Email Integration behavior
remain deferred and unchanged.

## Implementation and boundary review

Implemented the decisions above in eight frontend files. Existing authoritative
responses supply every displayed fact; **no backend/read-model change was required**.
Known assignment reasons are translated to canonical Admin wording at the display
boundary. Pre-start availability uses server `canStart` and the known early-entry
reason; no device-time permission inference was added. Start failures use safe
Applicant copy rather than revealing configuration/content requirements.

The normal Admin result has one prominent Computed Result. A reconsidered record
instead leads with **Final Decision: Passed — Reconsidered**, with the original
computed FAILED shown once in the score evidence. The shared breakdown also
retains Applicant result numbers and the computed outcome. Essay score is shown
in the aggregate result and in its evaluation context; evaluator/time and exact
response have their primary home in Essay Evaluation. Appointment and
reconsideration controls use presentation props to appear in their relevant page
sections; their handlers, bodies, permission flags and repeated-click guards are
unchanged. Submission details retain the reference and recorded start; deadline
and content binding remain in the authoritative receipt/state.
